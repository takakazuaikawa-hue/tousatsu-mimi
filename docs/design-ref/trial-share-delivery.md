## 3. 共有の動き
- **Xで感想をシェア**：X の投稿画面（`https://x.com/intent/post`）を新しいタブで開き、次の文を入れる。投稿の確定は本人。自動投稿・ログイン情報の取得・X API は無し。スマホでも共有メニューではなく X の投稿画面へ進む。
  ```
  『ミミのテキサスホールデムポーカー』体験版を遊びました！
  ［共有先の公開URL］
  #ミミのテキサスホールデムポーカー
  ```
- 共有先が未設定の間は、このボタンは押せない形で出し、下に「共有先のページを用意中です」と出す。
- **共有画像を保存**：画像を保存の形で開く（`download` 指定）。保存できない端末は、案内の「画像を開いて」から長押しで保存。保存できたかはゲームから分からないので、成功の知らせは出さない。
- 共有しなくても「ロビーへ」「製品版のページへ」はそのまま使える。投稿は進行の条件ではなく、遊んでいる途中には促さない。
- タイトル画面の共有は今までどおり（「体験版を遊びました」とは出さない）。共有先が未設定の間は「用意中」と知らせて共有しない。

## 7. 公開前に設定が必要なもの
共有先と「製品版のページへ」の移動先は、別々の設定です。どちらも書き出し済みの体験版の `index.html` の1行（`<head>` の最後の `<script>`）にあり、書き出しの道具を使わずにその場で書き換えられます。

```html
<script>window.MIMI_TRIAL = true; window.MIMI_STORE_URL = "../../games/texas-holdem/"; window.MIMI_SHARE_URL = "";</script>
```

- `MIMI_SHARE_URL`：X とタイトル画面の共有に載せる、一般公開の作品紹介ページの URL。`https://` で始まる完全な URL を `""` の中に書く（空のままなら「共有先を用意中」と出る）。
- `MIMI_STORE_URL`：終了画面の「製品版のページへ」の移動先。HP の中なら相対の場所でよい。
- **公開前**（まだ誰も遊んでいない・まとめてダウンロードしていない）なら、この1行を書き換えるだけでよい。
- **公開後**に書き換える時は、同じフォルダーの `offline-files.json` の `index.html` の `hash`（中身の SHA-1 の先頭12文字）と `size` も新しい `index.html` に合わせる。合わせないと、先にまとめてダウンロードした人の端末に古い設定が残る。制作側に頼めば `node tools/make-offline-files.mjs <体験版のフォルダー>` で作り直す。
- 制作側で書き出し直す場合は `--share <URL>` と `--store <移動先>` で同じ値が入る（ローカル・非公開プレビュー・旧個人の URL は書き出しが止まる）。

| 項目 | 今の値 | 設定の仕方 |
|---|---|---|
| 共有先（一般公開の作品紹介ページの URL） | 未設定 | 書き出しの `--share https://…` |
| 作品紹介ページへの移動先（終了画面の「製品版のページへ」） | `../../games/texas-holdem/`（HP の中の相対） | 書き出しの `--store` |
| X の投稿の文 | 上の3行 | `game.js` の `showTrialEnd` の `xText` |
