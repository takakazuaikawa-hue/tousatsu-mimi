# ホーム第5回：FABLE の答え（勝つたびに育つ劇場／常時の動き／金の図柄）

前提として見たもの：home-r5-brief.md、home-pc.png / home-phone.png、home.js（HOME_PLACEMENT・mountHomeMotion・renderHomeLedger 相当）、index.html の tpl-lobby、assets/ui/home/stage-empty.webp。
実装上の大事な事実：リコと舞台は scene.webp の1枚絵（他衣装は stage-empty.webp＋立ち絵）。なので「絵の中身を動かす」ことはできず、できるのは「絵の上に重ねる層を足す・引く」か「絵全体を動かす」かの二択。以下はすべてその前提で組んでいる。

---

## 1. 勝ち数 0→5 でホームがどう育つか

### 結論：主題は「時計が進み、劇場に灯が入っていく」
この舞台は「巨大時計台の中の劇場」。だから進行の表現は **「時計の文字盤の数字 I〜V が勝つたびに一つずつ灯る」** を芯にする。台帳の相手も Ⅰ〜Ⅴ、文字盤にもローマ数字がある。同じ記号が二か所で呼応するので、説明の文字を一切増やさずに「今は第何幕か」が伝わる。
その周りに「客席の灯り」「幕」「卓の上の物」が一段ずつ足されていく。上質なスマホゲームのロビーが育つ時の定石は「新しい物が増える」より **「同じ場所が明るく・豊かになる」** こと。部品を増やして散らかさず、照明と密度で見せる。

### 段階ごとの変化（何が・どこに・どう）

| 勝ち数 | 時計（中央奥） | 客席の灯り（上部左右のシャンデリア・燭台） | 幕（画面左右端の前景） | 卓の上（下段） | 右の額・札 |
|---|---|---|---|---|---|
| 0 | 文字盤は今のまま。数字は灯らない。光はやや弱く、周辺減光を今より一段濃く（「開演前」） | 消灯。上の左右コーナーに暗めの層を被せ、燭台の炎だけ小さく | 幕が左右から各 8%（スマホは 5%）舞台に掛かっている。房は垂れたまま | 卓は素の状態。台帳に封蝋なし | 額はⅠリコ。札は通常 |
| 1（Ⅰ勝利） | 文字盤の「I」が金色に灯る（小さな光輪） | 卓に一番近い燭台群に火が入る（中央寄りの暗層が消える） | 幕が一段開く（各 6%） | 台帳Ⅰに封蝋。卓の手前にチップの小山が1つ | 額がⅡに掛け替わる |
| 2 | 「I」「II」が灯る。文字盤の光が少し強まる | 左右の中段の燭台に火 | 各 4% | 封蝋2。チップ2山＋伏せ札1枚 | 額Ⅲ |
| 3 | 「III」まで灯り、文字盤の裏の歯車の影が見えはじめる（コードで薄く回す） | 上段のシャンデリアに火（左右の暗層が消える） | 各 2% | 封蝋3。チップ3山 | 額Ⅳ |
| 4 | 「IV」まで灯る。長針の先の光（既存）が強く、周期が 6→4 秒に | 全灯。シャンデリアの結晶がきらめく（星型の点滅） | 幕は完全に開き、房が結ばれている | 封蝋4。チップ4山＋広げた札 | 額Ⅴ。札の「勝てば…」の縁が金に光る |
| 5（全卓制覇） | I〜V 全点灯＋XII が白金に灯り「満ちた」感じ。文字盤全体がゆっくり呼吸（明滅 8 秒周期） | 全灯＋金粉が光の筋の中を漂う（2層・軽い） | 開ききり | 封蝋5。卓の中央に小さな金の杯か王冠（1枚絵・任意） | 額は「再戦」。札は金地に変わる |

ポイント
- **0 の状態をいまより少し暗くする**のが肝。今の絵はすでに全灯なので、今を「5」とし、そこから引き算して 0 を作る。足し算ではなく引き算で段階を作れば、絵を描き直さずコードの被せ層だけで実現できる。
- 変化は「中央（時計）→ 卓の周り → 客席上段」の順で**内から外へ**広がる。奥行きが「見えてくる」のと同じ心理効果を、カメラを動かさずに得られる。
- 衣装変更で stage-empty.webp に切り替わっても、すべて「被せ層」なので同じ仕組みがそのまま効く。

### 「カメラが一段ずつ引いて奥行きが見える」案の評価
良い点
- 「引き」という言葉通りで、劇場の広さが分かる気持ちよさがある。実装は背景の scale を変えるだけで安価。

悪い点（こちらが重い）
- **リコと舞台が同じ1枚絵**なので、引くとリコも小さくなる。ホームの主役の顔が段階ごとに縮むのは本末転倒。スマホ横では今でさえ小さい。
- 引くには「引いた先の絵」が要る。同じ絵をズームで誤魔化すと 0 の状態は拡大＝画質劣化、5 段分を別に描けば ChatGPT で5枚の整合を取る必要があり「切り貼りするとクオリティが落ちる」そのものになる。
- 吊り札・額・台帳は画面端に固定なので、絵だけ引くと部品と絵の位置関係（卓の縁、鎖の吊り元）が段階ごとにずれる。

結論：**大きな引きはやらない。ただし「微かな引き」は取り入れる。** 0 で背景を 1.06 倍、5 で 1.00 倍（1 段 1.2%）。transform-origin は卓の縁の中央（リコの肘の位置）に置き、リコは実質動かず、周辺だけがわずかに広がる。周辺減光がゆるむ変化と合わせると「視野が開いていく」感じが出る。これは絵の追加なし・コードのみ。

## 2. 勝った直後にホームへ戻った時の、一度だけの演出

名前：**「開幕の儀」**（約 2.6 秒。画面タップ／クリックで即終端状態へ）。勝利フラグが前回描画時より増えていた時だけ走る。動き軽減ではフェード 1 回で終端状態を出す。

| 時刻 | 何が起こるか |
|---|---|
| 0.0s | ホームは「勝つ前」の段階の姿で入場（いつもの入場アニメは省略して静止で出す）。音は環境音のみ。 |
| 0.3s | 文字盤の該当数字（例：Ⅱ）が **奥から手前へ**灯る：光輪が scale 0.6→1.0、ぼかし 12px→2px、ごく小さな鐘の音（チーン 1 回）。長針の先の光が一度強く走る（既存 .h15-tip を流用）。 |
| 0.8s | **封蝋が落ちる**：台帳の該当枠に seal.webp が scale 1.8・透明度 0 から 1.0・不透明へ 180ms で落ち、着地で 4px 沈んで戻る（ばね 1 回だけ）。着地の瞬間、蝋の面に金の反射が斜めに一度走る。台帳全体が 2px 揺れる。 |
| 1.2s | **額の掛け替え**：今夜の相手の額が鎖で 60px 上に引き上がり（鎖が伸びる）、透明に。120ms 後、次の相手の額が上から 80px 降りてきて鎖の長さに達して止まり、1.2° の振り子で2往復して静止。肖像が替わる瞬間は額の裏側（額の webp を 50% 暗く）を一瞬見せると「掛け替えた」実感が出る。 |
| 1.6s | **灯が入る**：その段階で点く燭台群の暗層が、卓に近い順に 80ms 刻みで消えていく（中央から外へ）。各炎は点いた直後 300ms だけ少し大きく。幕が一段分、左右へ 600ms で開く（ease-out）。背景の微かな引きも同時。 |
| 2.1s | **札の更新**：「今夜の卓へ」の札が一度跳ね（既存 h15-hop）、賞金の数字が旧→新へ 400ms で数字が回る。金の光沢の一掃き。 |
| 2.4s | リコの台詞が「勝った直後専用」の一言に差し替わる（その入場のみ。次回からは通常）。 |
| 2.6s | 以後は通常のホームの常時動作に接続。 |

Ⅴ（全卓制覇）の時だけ追加：1.6s で全灯のあと、文字盤の XII が白金に灯り、金粉の層がゆっくり立ち上がる（粒子ではなく、点を散らした 2 枚のタイル背景を縦に流すだけ）。打ち上げや紙吹雪はしない。品位はここで決まる。

設計上の注意
- 全部「段階 n-1 の姿 → 段階 n の姿」への補間で作る。つまり 1 の表と完全に同じ状態変数を使い、演出は「その変数を時間差で切り替える」だけ。演出用の特別な見た目を作らない（作ると終端状態とずれて安っぽくなる）。
- 既存の入場アニメ（fx/fy/frx）と重ねると騒がしいので、儀式中は入場アニメを切る。
- 途中タップで終端状態へ飛ばせる。これは必須（2 回目以降の周回者のため）。

## 3. 常時動いている物（優先順）

いずれも「GPU で済む transform / opacity のみ」「要素数は固定・少数」「動き軽減で停止」「タブ非表示で停止（既存の home-paused に乗せる）」。

1. **燭台の炎の揺らぎ**（コードのみ）：画面上の燭台・シャンデリアの位置に、小さな放射状グラデーション（直径 40〜90px、金橙）を 8〜10 個置き、各々別周期（2.3〜4.1 秒）で opacity 0.35〜0.7、scale 0.96〜1.04 を揺らす。これだけで「生きている劇場」になる。段階 1 の灯り変化と同じ要素を使う（点いていない燭台は非表示）。
2. **文字盤の裏の歯車の影**（コードのみ）：文字盤と同心の円に、低コントラストの放射状の影（conic-gradient を mask で円に切った 1 要素）を 90 秒で 1 回転。目で追えない速さだが、止まると「静止画だった」と気づく類の動き。
3. **光の筋の中の金粉**（コードのみ）：時計からの逆光の帯の中だけ（mask）に、点を散らした小さなタイル 2 枚を背景にし、縦にゆっくり流す（1 枚 40 秒、もう 1 枚 65 秒、逆方向にわずかに横揺れ）。粒子を JS で動かさない。段階 5 で濃くなる。
4. **吊り札・額の揺れの「風」**（既存の強化）：今の個別の揺れは良い。これに 20〜30 秒に 1 回、左の札 5 枚を上から順に 60ms ずつ遅らせて同じ方向に 0.4° 振る「ひと吹き」を足す。札同士が同じ風に答えると立体感が一段上がる。額は鎖なので遅れて 0.6° 反応。
5. **シャンデリアのきらめき**（コードのみ）：4 本角の小さな星（CSS で 6px）を 6〜8 点に置き、1 点ずつ 0.5 秒で現れて消える。同時に光るのは常に 1〜2 点だけ。段階 3 以降のみ。
6. **押せる物の呼吸**：ホバー／フォーカスで吊り札が translateZ +14px、金縁に斜めの光沢が 500ms で一度走る。触れていない時は動かない（常時の「ゆらゆら」を増やすのではなく、触れると応える方向）。スマホでは押下時に同じ応答。
7. **コイン数の回転**：所持コインが変わった時だけ、数字が 400ms で回って新しい値になる。常時ではないが「動きが少ない」印象を下げるのはこういう応答。
8. **リコのまばたき**（要・絵、任意）：目を閉じた差分を目の周りだけ切り抜いて重ね、8〜14 秒に 1 回 120ms。ChatGPT で同じ絵の局所差分は位置がずれやすいので、まず試し描き 1 枚で判断。ずれたら採用しない。

やらない方が良いもの：画面全体を常時ゆっくり拡縮する「Ken Burns」（酔う・安っぽい）、霧・煙の大面積アニメ（PC が非力）、キャラ周りの光のリング（丸で囲む禁止に抵触）。

## 4. 金の浮き彫りで描くアイコン（図柄案・各1行）

共通の描き方：部品と同じ「深紅の地に金の浮き彫り」。線の太さは 24px グリッドで 2.5px 相当、角は丸め、ハイライトは左上。純緑の地で、1 アイコン＝1 枚、同じプロンプト頭で 9 枚揃える。

案内札（左）
- **交換所**：両皿に硬貨を載せた小さな天秤（グラーノの商会の秤）。
- **コレクション**：リボンで束ねた 3 枚の絵札、上の 1 枚だけ扇に少し開く。
- **ぱにゅぱにゅ**：結び目がほどけかけた絹のリボン一本（札に小窓があるので小さめ・控えめ）。
- **リコの教室**：開いた教本の上に角帽、脇に短いチョーク。
- **衣装**：ウサ耳のカチューシャと蝶タイを一組に（この舞台の衣装の記号そのもの）。

八角金具（右上）
- **タイトルへ**：劇場の両開き扉、片側だけ少し開いて光が漏れる。
- **贈り物**：リボン掛けの小箱、蓋がわずかに浮いて中から光（受取前は既存の赤点を蓋の上に）。
- **コイン**：ウサギの横顔を打ち出した一枚の硬貨（数字は横にコードで）。
- **設定**：8 歯の歯車、中央に小さな赤い石（時計台の歯車と同じ意匠）。

## 5. 新しく描く絵（最小）とコードで済む物

### ChatGPT で描く（純緑の地・文字なし）
| # | 絵 | 枚数 | 用途 | 優先 |
|---|---|---|---|---|
| A | 前景の幕（左半分）＋房付きの留め紐 | 1〜2 | 段階 0→4 の「幕が開く」。右は左を反転 | 高 |
| B | 金の浮き彫りアイコン 9 種 | 9 | 第4項。今の線画 SVG を置き換える | 高 |
| C | チップの小山（赤・金の 2 色）と伏せ札・開き札の 1 組 | 1〜2 | 卓の上の蓄積。拡縮と左右反転で 5 段分を作る | 中 |
| D | 全卓制覇の小さな金の杯（または王冠） | 1 | 段階 5 の卓の中央 | 低・任意 |
| E | リコの目閉じ差分（目の周りだけ） | 1 | 第3項 8。ずれたら不採用 | 低・試し |

描かなくてよい物：数字の光輪、燭台の炎、歯車の影、金粉、星のきらめき、封蝋の落下、額の掛け替え、幕の移動、周辺減光、微かな引き、数字回転 ——全部コード。scene.webp と stage-empty.webp には触らない（整合を崩さないため）。

### コードだけでできる物（まとめ）
- 進行の状態変数：`--stage`（0〜5）を .home-stage に持たせ、すべての層の opacity / transform を CSS の計算に任せる。JS は値を 1 つ入れるだけ。
- 文字盤の数字 I〜V の光輪：文字盤上の 5 点に放射状グラデーションの span（位置は 1280×800 基準の % 指定、fitHomeStage の既存の幅計算に乗せる）。
- 客席の暗層：上左右 3 つの半透明の黒い層（mask で中央のリコを避ける）。段階に応じて 1 枚ずつ opacity 0 へ。
- 燭台の炎・きらめき・歯車・金粉：第3項の通り、固定個数の要素と CSS keyframes。
- 封蝋の落下・額の掛け替え・幕の移動・札の跳ね・数字回転：第2項。`--stage` の切り替えを setTimeout で段階的に行う 1 関数。
- 動き軽減・非表示タブ：既存の reduce / home-paused にすべての animation を紐づける（`.home-paused *, .h15-reduce * { animation-play-state: paused }` の一本で済む）。
- スマホ横：幕の掛かりは各 5% 以内、燭台の炎は 6 個に減らす、金粉は 1 層。押せる領域は変えない。

### 実装の順番の提案
1. `--stage` と暗層・数字の光輪・微かな引き（絵なし。これだけで「進んだ」が伝わる）
2. 燭台の炎・歯車・金粉（絵なし。「動きが少ない」が消える）
3. 開幕の儀（絵なし）
4. 幕（A）→ アイコン（B）→ チップ（C）の順で絵を足す
