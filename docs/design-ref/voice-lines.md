# 声を付ける台詞の棚卸しと提案（Irodori-TTS、2026-10-18）

声の設計は `docs/design-ref/voice-casting.md`。ここは「どの台詞に声を付けるか」の提案。
行番号は 2026-10-18 の作業ツリー（game.js は編集中で行がずれることがある。関数名・定数名を正とする）。
生成は CPU で 1本 約5〜8分（以下 6分で見積もる）なので、**本数がそのまま工数**になる。

## 0. 要約

- ゲーム内の台詞テキストは全部で **約1,500行**。そのうち毎回出る卓の台詞（対戦中の吹き出し約315行）と講義（約240行）が大半を占める。全部に声を付けるのは非現実的。
- 方針は3つ。
  1. **短い掛け声（チェック・コール・レイズ・オールイン・降り・勝ち・負け）をキャラ別に固定クリップ化し、何度でも使い回す**。1日に何百回も聞く所は、ここだけで足りる。
  2. **一度しか聞かない山場（プロローグ・エンディング・幕間の相手の一言・初手の出会い台詞）は、台詞そのままを声にする**。
  3. 講義・用語集・ショップ・ミニゲーム・読み合いの説明文は声なし（文字のまま）。
- 第1弾は **101本（約10時間）**、第2弾 +145本、第3弾 +88本、全部で **約334本（約33時間）**。
- 掛け声の文言は、**既存の台詞をそのまま流用できるものがほとんど**。新しく書くのは約22文言だけ（第3章に「既存／新規」を明記）。

## 1. 台詞の棚卸し

### 1.1 ポーカーの動作の掛け声：今、文字は出ているか

## 2. 推奨表

「声あり」＝台詞そのまま、「掛け声に置換」＝文字の台詞はそのままで、動作に合わせて短い固定クリップを鳴らす、「一部」＝代表だけ、「声なし」。

| カテゴリ | 判定 | 理由 |
|---|---|---|
| ポーカー動作の掛け声（チェック・コール・ベット・レイズ・オールイン・降り・勝ち・負け）A,F | **掛け声に置換**（第3章の固定クリップ） | 最も聞く回数が多い。バリエーション文を全部声にすると約150本。短い固定クリップなら7人×13本で済み、何度聞いても疲れない長さと言い回しにできる。 |
| 手の開始 B | **一部**：初手のみ1人1本（そのまま）。第2弾で各人あと2本 | 毎ハンドで同じ声が鳴ると煩い。出会いの一言として初手だけ鳴らす。 |

### 鳴らし方の約束（飽きさせない）

- **確率で鳴らす**：`allstar-ui.js` の動作の台詞（667付近）と同じ作り方。目安は オールイン 100%、レイズ・ベット 60%、降り 50%、勝ち／負け 50%、コール 35%、チェック 30%。
- **同じクリップを2回続けて鳴らさない**。直近の2本は避ける。
- **同時に2人が喋らない**：`playEmote` の 1.6 秒の間引き（`__emoteLast`、18057付近）と同じ考え方で、声は常に1本。カットイン中（`showOpponentCutIn` 18349 / `showAllInCutIn` 14238 / `showClutchCutIn` 775）は、そのカットインの声を優先する。
- **吹き出しとの食い違い**：相手の吹き出しには意図別の文（例：セリナの「このサイズの意味、考えてください。」）が同時に出る。掛け声は短い合いの手として鳴らし、吹き出しの文言は声にしない。掛け声と吹き出しが矛盾して見えるなら（例：「チェック」と鳴ったのに吹き出しが「全部いくよ」）、動作の掛け声を鳴らす時は吹き出しの意図別文を出さない、のどちらかに寄せる（要判断、第6章）。

### 5.3 音量・ON/OFF（既存の設定キー）

- 設定は `save`（localStorage の `SAVE_KEY`、game.js:11）に入っている。

  - 効果音：`sfxOn`（既定 true、274）、`sfxVolume`（既定 60、273）。`isSfxOn()` 364、`sfxVolFloat()` 365。`mpSfx()`（10071）は `isSfxOn()` で止め、`_mpSfxScale = sfxVolFloat()` を掛ける。
  - 消音スイッチ：`forceSound`（既定 false、275）。`isForceSound()` 9990、`applyAudioSession()` 9991、`routeThroughWebAudio()` 10013。
  - 全部の ON/OFF：`toggleAllAudio()` 9092（`bgmOn` と `sfxOn` を同時に切り替える）、`isAnyAudioOn()` 9079。
- 設定画面：`showSettingsModal()` 4779。スライダーは `data-volume="bgm"` / `data-volume="sfx"`（4804）で、変更は 4855 付近で保存。ロビー下の `renderLobbyBottomPanel()` 4757。新規セーブの既定値は `defaultSave()` 225、検査は `normalizeSave()` 292（`sfxVolume` の検査は 319）。「最初からやり直す」で持ち越す設定は `KEEP_KEYS`（7730）。
- 提案：
  - 声は**効果音の仲間**として扱い、`isSfxOn()` が false なら鳴らさない。さらに `voiceOn`（既定 true）と `voiceVolume`（既定 80）を足す（`defaultSave` / `normalizeSave` / `KEEP_KEYS` / `showSettingsModal` の4か所）。最終音量は `voiceVolume / 100`（`sfxVolume` は掛けない。台詞が効果音より小さくなると聞こえないため）。「音まるごと OFF」（`toggleAllAudio`）で無音になる。
  - **BGM は声の間だけ下げる（ダッキング）**：`#scene-bgm-audio`（`playSceneBgm` 9041 が音量を決める）と `#ending-bgm-audio`（`applyBgmVolume` で最大 1.6倍にしている）の `volume` を 30%減らし、終わったら `applyBgmVolume()` で戻す。エンディングは特に必要。
  - 再生は **Web Audio**（`mpAudioCtx()` 9969 の `AudioContext`）に `decodeAudioData` したバッファを `GainNode` 経由で流す。これなら `forceSound` の挙動（iOS の消音スイッチ）が効果音と同じになり、タップ直後の遅延も少ない。HTMLAudio にするなら `routeThroughWebAudio()` を通す。
  - 先読み：ロードの方針（遅れて鳴ると興ざめ）に従い、**場面の前にまとめて読む**。対戦なら `warmNextBattle`（12835）の流れでその相手の `bark_*` ＋ `ready_1` ＋ `react_allin`（約15本・300〜450KB）を、プロローグ・エンディング・幕間は表示の前に。起動時には読まない（`PRELOAD_AUDIO` は空のまま、18735付近のコメントの通り）。
  - 自動再生：声はすべてタップ（ボタン）の後に鳴るので iOS の制限に当たらない。最初の1回は `mpAudioCtx()` の `resume()` が必要。

## 6. 決めてほしいこと・リスク

1. **掛け声と吹き出しの関係**：相手の吹き出しには意図別の文（例：「あなたのレンジでは厳しいはず。」）が出続ける。そこへ「チェック」と声が鳴ると、文字と声が別々のことを言う。案：(a) 声は合いの手として併用（工数最小、本書の想定）、(b) 声を鳴らす動作では吹き出しを「チェック」などの短い動作表示に変える（演出の変更が大きい）。
2. **心理バトルの声色**：ブラフ時と本物の時で抑揚が変わると読みの答えが漏れる。第2弾の17本は、ブラフ／本物で声色を揃える（または毎回似た抑揚にする）指定で作る。
3. **本気のリコの声を別に作るか**：`rico_serious` は別の声として掛け声13本＋初手・反応の2本が要る（合計15本）。リコの声を「低く冷たく」へ変えるだけなら同じ参照音声から作れる。
4. **ミミの掛け声は新規が多い**（約13文言）。心の声ではなく口に出す台詞として、画面に字幕を出すかどうか。出さないなら音だけ。
5. **新規文言は生成前にユーザーの確認が要る**（セリフは作品の声）。第1弾の新規は13文言。
6. `game.js` を編集中の別作業と衝突しないよう、声の再生関数は独立ファイル（`voice.js`）にして、game.js への変更は「呼び出しを足す」だけにする。
7. 生成の長さの確認：長い文（エンディングのミミ「……でも、振り返ってみて、気づきました。…」は約60字）は1本で8分を超える可能性がある。第1弾の中で最長の10本を先に試して時間を測る。
